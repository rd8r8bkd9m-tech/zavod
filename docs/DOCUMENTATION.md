# Content Factory AI — Техническая документация

**Версия:** 1.0 (MVP Client-Side)  
**Дата:** Октябрь 2023  
**Статус:** Функциональный прототип (MVP)

---

## 1. Обзор проекта

**Content Factory AI (Контент-Завод)** — это SaaS-платформа для автоматизации полного цикла контент-маркетинга. Система позволяет превращать короткие идеи, новости или ссылки на видео (YouTube) в пакеты контента для различных социальных сетей (Telegram, VK, Dzen и др.), используя генеративный ИИ (Google Gemini).

### Ключевые возможности:
*   **Мульти-форматность:** Генерация постов под специфику разных площадок из одного источника.
*   **Repurposing:** Автоматическая переработка YouTube-видео в текстовые посты (статьи, треды, саммари).
*   **Brand Memory:** Учет Tone of Voice и контекста бренда при генерации.
*   **Автопилот:** Агенты, работающие в фоновом режиме по расписанию.
*   **Интеграции:** Прямая публикация в Telegram (реализовано) и эмуляция других платформ.

## 2. Технологический стек

### Frontend (SPA)
*   **Core:** React 19 + TypeScript + Vite (через ES Modules в браузере).
*   **Routing:** `react-router-dom` (HashRouter).
*   **State Management:** `zustand` + `persist` middleware (хранение состояния в LocalStorage).
*   **Styling:** Tailwind CSS + кастомная дизайн-система (Shadcn-like components).
*   **Icons:** Heroicons (SVG).

### AI & API
*   **LLM:** Google Gemini 1.5 Flash (через `@google/genai` SDK).
*   **Telegram:** Прямые HTTP-запросы к Telegram Bot API (`fetch`).

### Текущая Архитектура (Client-Side MVP)
Приложение работает полностью в браузере. База данных отсутствует, все данные (посты, настройки, токены) сохраняются в `localStorage` пользователя. Это обеспечивает приватность и простоту развертывания демо-версии.

## 3. Реализованный функционал

### 3.1. Модуль "Конвейер" (Factory)
Центральный хаб генерации. Имеет два режима:

1.  **Полу-автоматический:**
    *   **Вход:** Текст идеи или URL (детектируется автоматически).
    *   **Video-to-Text:** Если вставлена ссылка, система эмулирует анализ видео (получение транскрипта, выделение хуков) и генерирует контент на его основе.
    *   **Настройки:** Выбор тональности, платформ.
    *   **Визуализация:** Отображение этапов работы ИИ ("думает", "пишет").
    *   **Результат:** Черновики сохраняются в Библиотеку.

2.  **Полный Автопилот:**
    *   Создание "Агентов" с заданными темами и расписанием.
    *   Карточки агентов с индикацией статуса, платформами и датой последнего запуска.
    *   Кнопка принудительного запуска агента (`handleForceRun`), которая генерирует контент в фоновом режиме.

### 3.2. Редактор и Публикация (Editor)
*   **Редактирование:** Изменение заголовка и тела поста.
*   **Генератор UTM:** Встроенный модальный инструмент для добавления размеченных ссылок в текст.
*   **Workflow:** Статусы (Idea -> Draft -> Review -> Approved -> Scheduled -> Published).
*   **Публикация:**
    *   **Telegram:** Реальная интеграция. Отправляет сообщение с Inline-кнопками (Like/Dislike/Link) в указанный канал/чат.
    *   **Другие:** Эмуляция задержки API и успешного ответа.

### 3.3. Исследования (Research)
*   **Поиск трендов:** Эмуляция поиска виральных тем в соцсетях с метриками (ER, Views).
*   **Анализ видео:** Отдельный таб для превращения ссылки YouTube в "Идею" (сохраняется Summary и Hooks в бэклог).

### 3.4. Библиотека и Календарь
*   **Библиотека:** Таблица всех материалов с фильтрацией по платформам и поиском. Удаление и переход к редактированию.
*   **Календарь:** Месячный вид. Отображает запланированные и опубликованные посты.

### 3.5. Настройки и Интеграции
*   **Brand Memory:** Глобальное поле для описания компании, которое подмешивается во все промпты к ИИ.
*   **Integrations Manager:**
    *   Ввод API токенов (хранятся локально).
    *   Для Telegram: Валидация токена через `getMe` и сохранение `chat_id`.
*   **Темизация:** Переключение Light/Dark mode.

## 4. Структура данных (Store)

Основное состояние управляется в `store/useAppStore.ts`.

| Сущность | Описание |
| :--- | :--- |
| `library` | Массив `ContentItem`. Хранит все посты (id, title, body, status, platform, dates). |
| `integrations` | Настройки подключений (API Keys, Chat IDs, статус подключения). |
| `brandInfo` | Строка контекста бренда для ИИ. |
| `credits` | Внутренняя валюта (токены) для ограничения генераций. |
| `autoPilotTasks` | Конфигурации агентов автопилота. |

## 5. Интеграции API

### Google Gemini API
*   Используется модель `gemini-3-flash-preview`.
*   Промпт инжиниринг: System Instructions задают роль маркетолога и специфику каждой соцсети (Dzen = лонгрид, Telegram = короткий пост и т.д.).
*   Формат ответа: JSON Schema (массив объектов).

### Telegram Bot API
*   Метод: `sendMessage`.
*   Особенности: Отправка `parse_mode: HTML` и `inline_keyboard` для сбора реакций.

## 6. GAP-Анализ: Чего не хватает (Roadmap)

Для перевода проекта из MVP в Production необходимо реализовать следующее:

### 6.1. Backend (High Priority)
*   [ ] **Переезд с LocalStorage на PostgreSQL:** Необходима реальная база данных для хранения контента и пользователей.
*   [ ] **Auth System:** Интеграция Clerk или NextAuth для регистрации и разделения доступов.
*   [ ] **Server-Side API:** Перенос логики генерации и хранения ключей (`API_KEY`) на сервер (Next.js API Routes или NestJS) для безопасности.

### 6.2. Расширение ИИ
*   [ ] **Real Video Analysis:** Замена `setTimeout` заглушки на реальный пайплайн:
    1.  YouTube Data API (получение метаданных).
    2.  YouTube Transcript API (получение текста).
    3.  Gemini 1.5 Pro (саммаризация большого контекста).
*   [ ] **Image Generation:** Интеграция Replicate (Flux/Midjourney) или OpenAI (DALL-E 3) для генерации обложек к постам.

### 6.3. Интеграции платформ
*   [ ] **VK Admin API:** Реализовать реальный постинг на стену сообщества.
*   [ ] **WordPress XML-RPC/REST API:** Публикация статей в блог.
*   [ ] **Pinterest:** Публикация пинов.

### 6.4. Автоматизация (Server-Side)
*   [ ] **Task Queue:** Внедрение Redis + BullMQ для обработки задач Автопилота и отложенного постинга (сейчас работает только пока открыта вкладка браузера).
*   [ ] **Cron Jobs:** Планировщик для ежедневных задач агентов.

### 6.5. Аналитика
*   [ ] **Сбор данных:** Webhooks от платформ для обновления счетчиков просмотров/лайков в реальном времени.

## 7. Инструкция по локальному запуску

Так как проект использует ES Modules и CDN (через `index.html`), сборка Node.js не является строго обязательной для запуска *текущей версии*, но рекомендуется для разработки.

1.  **Установка зависимостей:**
    ```bash
    npm install
    ```

2.  **Настройка окружения:**
    Создайте файл `.env` в корне (хотя в текущей версии ключи вводятся в UI или `process.env` подставляется сборщиком):
    ```env
    API_KEY=your_google_gemini_key
    ```

3.  **Запуск:**
    ```bash
    npm run dev
    ```

4.  **Использование:**
    *   Откройте `http://localhost:5173` (или порт, выданный Vite).
    *   Зайдите в **Настройки**, введите (опционально) API ключ Telegram бота и Chat ID.
    *   Перейдите в **Контент-Цех (Factory)** и начните творить.
